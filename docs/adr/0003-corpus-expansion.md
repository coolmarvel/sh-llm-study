# ADR-0003 코퍼스 2차 확장

## 상황

v1.0 본 학습(`small-cpu`, 6.8M)은 근대문학 49만 토큰에서 2,100 스텝(≈17 에폭)부터 val 이 정체됐다 (best 5.485).
데이터가 병목이며, 브리프의 성공 기준("한글 프롬프트를 이어서 말이 되는 문단")에 가장 큰 영향을 주는 변수다.
브리프는 확장 후보로 "한국어 위키 일부"를 이미 열어 두었다 (`docs/brief.md`, ADR-0002).

## 결정

1. **출처**: 한국어 위키백과 API 의 plaintext extract. 커뮤니티 검수 문서(**알찬 글 148 + 좋은 글 253**) 전부와, 그 문서들이
   링크하는 이웃 문서 중 3,000자 이상을 등장 빈도순으로 더해 **약 1,000만 자**까지 (`scripts/download_wiki.py`). 무작위 문서는
   대부분 수백 자 단편이라 제외. 각주·외부 링크·같이 보기 절 제거.
2. **라이선스**: CC BY-SA 4.0. `data/corpus/WIKI-LICENSE.md` 에 출처·문서 목록 기록. 학습 모델·생성물은 학습용·비공개.
3. **혼합**: `korean-mixed.txt` = 근대문학 합본 + 위키 합본. 근대문학만 쓰는 `korean-classics.txt` 는 그대로 남긴다 (1~9장 노트북은 계속 이것을 쓴다).
4. **토크나이저 재학습**: 위키의 한자·숫자·라틴 문자는 기존 `bpe-8192.json` 에 없어 바이트로 쪼개진다 → 혼합 코퍼스로
   `bpe-8192-mixed.json` 을 새로 학습. 기존 체크포인트(`small-cpu`)는 기존 토크나이저로만 유효 (체크포인트가 토크나이저 이름을 기록).
5. **새 run**: `configs/mixed-cpu.yaml` → `data/checkpoints/mixed-cpu/`. small-cpu 는 비교용으로 보존.

## 대안

- 위키 덤프 전체(수 GB) 파싱, 이 PC 와 학습 시간에 과함. 필요하면 v2.
- 근대문학만 더 모으기(위키문헌), 퍼블릭 도메인 한글 문학은 양이 적고 문체가 편향됨.
- 확장 없이 모델을 줄이기, 과적합은 늦춰도 "말이 되는 문단"에는 도움이 안 됨.

## 결과

- (+) 데이터 10~20배. 현대 한국어·백과사전 문체가 더해져 프롬프트 다양성이 늘어난다.
- (−) 생성 문체가 위키 쪽으로 기운다 (양이 압도적). 근대문학 문체를 원하면 `korean-classics` 체크포인트를 쓴다.
- (−) 토크나이저 교체로 8~10장 노트북·대시보드는 run 별 토크나이저를 따라야 한다 (이미 체크포인트에 기록).
- 실제 수치와 생성 비교는 `docs/session-log.md` 2026-09-16 블록과 `docs/plans/0002-v1-1.md`.
