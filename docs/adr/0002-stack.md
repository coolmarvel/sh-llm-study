# ADR-0002: 스택·저장·디자인 결정

## 상태

Accepted (킥오프 위저드에서 사용자가 직접 선택, 2026-09-16)

## 맥락

`docs/brief.md` — CPU 만 있는 WSL PC 에서, LLM 개념을 챕터별로 배우며 소형 한글 GPT 를 밑바닥부터
구현한다. 산출물은 ① 챕터별 노트북 + 패키지 코드 ② 마크다운 교재(→PDF) ③ 웹 대시보드 세 가지.
학습자는 자바 배경이며 Python·PyTorch 는 처음이다.

## 결정

| 축 | 선택 | 위저드에서 제시했던 대안 |
|---|---|---|
| 모델 언어·프레임워크 | **Python 3.12 + PyTorch (CPU 빌드)** | NumPy 순수 구현 / Java 순수 구현 |
| 패키지 관리 | **uv** (`pyproject.toml` + `uv.lock`) | pip + venv |
| 실습 형태 | **Jupyter 노트북(챕터별) + `src/shllm/` 패키지** | 스크립트만 |
| 교재 | **`docs/book/` 마크다운 → PDF 한 권**(바탕화면 전달) | — |
| 대시보드 | **FastAPI + React(Vite·TypeScript) + Tailwind**, 도커로 8082 포트 | FastAPI+HTMX / Gradio |
| 저장 | **파일만** — `data/` → `/mnt/d/sh-llm-data` 심볼릭 링크 (corpus·tokenizers·checkpoints·runs), 학습 로그 JSONL | 파일 + SQLite |
| 코퍼스 | **한글 공개 텍스트** (퍼블릭 도메인 문학 → 한국어 위키 일부로 확장) | 영어 Tiny Shakespeare / 둘 다 |
| 디자인 | **oh-my-design, 베이스 레퍼런스 Linear, 차용 없음** | Toss / AWS / Naver |
| 하드웨어 | CPU 16코어, RAM 7.6GB, GPU 없음 | — |

## 근거

- **PyTorch**: LLM 분야 표준이라 레퍼런스(nanoGPT·논문 구현)가 가장 많다. 자동미분은 프레임워크에 맡기고
  모델 구조(토크나이저·어텐션·Transformer 블록)는 직접 짜는 것이 "원리 이해 vs 진도"의 균형점.
  NumPy 순수 구현은 역전파까지 손으로 짜야 해 진도가 느리고, Java 는 생태계·자료가 없어 막힐 때 참고할 곳이 없다.
  단, 4장(신경망 기초)에서 autograd 가 하는 일을 NumPy 로 한 번 재현해 블랙박스를 없앤다.
- **CPU 빌드**: GPU 가 없으므로 CUDA 없는 휠을 받아 설치 용량(≈200MB)과 시간을 줄인다.
  `torch.set_num_threads(16)` 로 코어를 다 쓴다. 수천만 파라미터 이하 모델은 CPU 로 충분히 학습 가능.
- **uv**: 잠금 파일로 재현 가능하고 venv 관리가 자동. 자바의 Gradle 처럼 "명령 하나로 환경 복원".
- **노트북 + 패키지 병행**: 노트북은 실험·시각화용, 검증된 코드는 `src/shllm/` 로 옮겨 테스트를 붙인다.
  노트북만 쓰면 코드가 흩어지고, 스크립트만 쓰면 중간 값을 들여다보기 어렵다.
- **FastAPI + React**: 백엔드가 같은 Python 이라 모델·체크포인트·로그를 그대로 읽는다. 어텐션 맵·토큰 확률
  같은 인터랙티브 시각화는 React 가 유리하고 oh-my-design 도 React 기준. Gradio 는 디자인 통제가 안 된다.
- **파일만**: 실험 수가 수십 개 수준이라 JSONL + 디렉토리 규약으로 충분. SQLite 는 필요해지면 ADR 로 추가.
- **D 드라이브 데이터**: 사용자가 윈도우 탐색기로 코퍼스·체크포인트를 보길 원함. 코드는 WSL 파일시스템에
  두어 Python·node 의 파일 접근 속도를 유지한다 (`/mnt/d` 는 9p 경유라 느림).
- **한글 코퍼스**: 결과물이 한글이라 품질 판단이 즉각적이고, 한글 토크나이징(자모/음절/BPE)이 영어보다
  배울 거리가 많다. 저작권 안전을 위해 퍼블릭 도메인·CC 텍스트만 쓴다.
- **Linear 레퍼런스**: 어두운 배경·밀도 높은 개발자 도구 스타일이 손실 곡선·어텐션 맵 대시보드에 맞는다.

## 결과

- (+) 레퍼런스가 풍부한 표준 스택. CPU 제약 안에서 학습·생성이 실제로 된다.
- (+) 데이터가 D 드라이브에 있어 윈도우에서 바로 열어볼 수 있고, 코드 저장소는 5GB 이내로 가볍다.
- (−) 학습 속도가 GPU 대비 수십 배 느리다 → 모델·코퍼스 크기를 챕터마다 명시적으로 제한한다.
- (−) 노트북은 git diff 가 지저분하다 → `nbstripout` 으로 출력을 제거하고 커밋한다.
- (−) 도커는 현재 WSL 통합이 꺼져 있어 대시보드 마일스톤 전에 Docker Desktop 설정에서 켜야 한다.
