# 2장 — BPE 토크나이저: 토큰 단위를 내가 정한다

1장의 `CharTokenizer` 는 두 가지가 고정돼 있다. 어휘 크기는 코퍼스의 글자 수(2,827)로 정해지고, 토큰 하나는 항상 글자
하나다. 그리고 코퍼스에 없던 글자가 들어오면 `KeyError` 로 죽는다. 이 장은 세 가지를 모두 푸는 **BPE(Byte Pair Encoding)**
를 직접 구현한다 — GPT-2 이후 거의 모든 LLM 이 쓰는 방식이다. 노트북 `notebooks/02-bpe-tokenizer.ipynb`, 코드
`src/shllm/tokenizer.py` 의 `BPETokenizer`.

## 2.1 왜 글자 단위로는 부족한가

| | 글자 단위 | 원하는 것 |
|---|---|---|
| 어휘 크기 | 코퍼스가 정함 (2,827) | 내가 정함 (모델 크기·속도와 맞춰서) |
| 토큰의 뜻 | 글자 하나 — "생각하였다" 는 5토큰 | 자주 쓰는 덩어리는 1토큰 |
| 처음 보는 글자 | 에러 | 어떻게든 인코딩 |
| 시퀀스 길이 | 글자 수 그대로 | 짧을수록 좋다 (어텐션 비용은 길이의 제곱 — 5장) |

## 2.2 알고리즘 — 가장 잦은 쌍을 합친다, 반복한다

BPE 는 원래 압축 알고리즘이다. 규칙은 하나:

```
1. 텍스트를 가장 작은 단위(바이트)의 열로 본다
2. 인접한 쌍 중 가장 자주 나오는 것을 찾아 새 토큰 하나로 합친다 → 병합 규칙에 추가
3. 어휘가 원하는 크기가 될 때까지 2 를 반복
```

노트북 §1 의 장난감 예 `aaabdaaabac`: 가장 잦은 쌍 `aa` 가 토큰 256, 다음 `ab` 가 257, 그 다음은 `256+257` = `aaab` 이
258 이 되어 `aaab d aaab a c` 다섯 토큰이 된다. (빈도가 같은 쌍은 먼저 나온 것을 고른다 — 구현마다 다를 수 있는 세부.)
병합 규칙 `merges` 는 **순서가 있는 리스트**고, 토큰 id 는 `256 + 순서` 다. 인코딩할 때는 텍스트를 바이트로 바꾼 뒤
"지금 있는 인접 쌍 중 **가장 먼저 배운** 쌍"부터 합친다 (`_encode_chunk`). 디코딩은 토큰마다 바이트열을 이어 붙여
UTF-8 로 되돌리는 것뿐이다.

```python
def decode(self, ids):
    return b"".join(self.vocab[i] for i in ids).decode("utf-8", errors="replace")
```

**바이트에서 출발하는 이유.** 기본 어휘가 바이트 256개면 세상의 어떤 문자열도 바이트열로는 표현되므로 "모르는 글자"가
없다. 코퍼스에 없던 `🐯` 도 4바이트로 쪼개져 들어가고 그대로 복원된다 (노트북 §4).

**조각 내기.** 텍스트 전체에서 쌍을 세면 `"다. 그"` 처럼 문장 경계를 넘는 토큰이 생긴다. 그래서 먼저 정규식 `PATTERN`
으로 조각(단어·구두점·공백)을 내고 조각 안에서만 병합한다. `" ?\w+"` 는 "앞 공백 하나 + 글자들" — GPT-2 처럼 공백을
단어 앞에 붙여 ` 담배` 가 한 토큰이 되게 한다. 조각을 `Counter` 로 묶으면 같은 어절을 수만 번 다시 세지 않는다
(코퍼스 35만 조각 → 고유 7.7만).

## 2.3 한글에서 생기는 일 — GPT 가 한글에 불리한 이유

한글 한 글자는 UTF-8 로 **3바이트**다 ("옛" = `EC 98 9B`). 바이트 256개에서 출발하면 글자 하나를 되살리는 데만 병합 두 번이
든다. 더 나쁜 것은 병합이 **빈도순**이라는 점이다. "옛" 의 마지막 바이트 `9B` 와 "날" 의 첫 바이트 `EB` 가 자주 붙어 나오면
`9B EB` 가 먼저 합쳐진다 — 글자 경계를 무시한 조각이 어휘를 채운다. 노트북 §2, 어휘 4,096 의 결과:

```
'옛날 옛적에 호랑이가 …' → ['<0xEC><0x98>', '<0x9B>', '<0xEB><0x82>', '<0xA0>', ' 옛' 의 일부 …]
```

병합 3,840개 중 629개(1/6)가 잘린 바이트 토큰이고, "옛" 은 앞뒤 글자에 따라 다른 조각으로 쪼개진다. 모델은 "옛"이라는 개념을
여러 토큰 조합으로 따로따로 배워야 한다. **실제 GPT-2·GPT-3 토크나이저에 한글을 넣으면 글자당 2~3 토큰이 나오는 것이
정확히 이 현상**이며, 같은 내용을 영어보다 2~3배 비싸게 처리하는 원인이다.

**해법 — 글자를 먼저 조립한다** (`char_first=True`, 기본값). 빈도 병합에 앞서, 코퍼스에 `min_char_count`(기본 2)번
이상 나온 여러 바이트짜리 글자를 바이트에서 통째로 만드는 병합을 먼저 넣는다. "옛"·"오"·"온" 처럼 앞 2바이트가 같은
글자는 중간 토큰을 공유하므로 병합 수는 글자 수 × 2 보다 적다(코퍼스에서 2,520개). 그 뒤의 빈도 병합은 **온전한 글자끼리만**
합쳐지고, 드문 글자(한 번 나온 한자)는 바이트로 남아 여전히 인코딩된다.

```
'옛날 옛적에 호랑이가 담배 피우던 …' → ['옛', '날', ' 옛', '적', '에', ' 호', '랑', '이가', ' 담배', ' 피우', '던', …, ' 생각하였다', '.']
```

이 방식은 SentencePiece 의 `byte_fallback` 과 같은 발상이다 — 정상 경로는 글자, 비상 경로는 바이트.

## 2.4 학습을 빠르게 — 증분 갱신

병합 한 번마다 모든 조각의 쌍을 다시 세면 코퍼스에서 한 번에 0.2초, 8천 번이면 25분이다. `BPETokenizer.train` 은
두 가지를 유지한다:

- `pair_counts` — 쌍 → 빈도
- `pair_words` — 쌍 → 그 쌍이 들어 있는 조각 번호들

병합할 때 `pair_words[best]` 의 조각만 고치고, 그 조각의 옛 쌍을 빼고 새 쌍을 더한다 (`apply_merge`). 뒤로 갈수록
빈도가 낮은 쌍이라 건드리는 조각이 적어 8,192 어휘가 약 1분 반에 끝난다. 자바로 치면 `Map<Pair, Integer>` 와
`Map<Pair, Set<Integer>>` 두 개를 같이 유지하는 인덱스다.

## 2.5 어휘 크기 ↔ 시퀀스 길이

병합은 순서대로 쌓이므로 앞쪽 k 개만 남기면 어휘 k+256 짜리 토크나이저가 된다 (`truncated`). 다시 학습 없이 어휘 크기를
바꿔 가며 코퍼스 114만 자가 몇 토큰이 되는지 잰다 (노트북 §3.1):

| 토크나이저 | 어휘 | 토큰 수 | 토큰당 글자 |
|---|---|---|---|
| 글자 단위 | 2,827 | 1,136,164 | 1.00 |
| BPE | 2,048 | 1,139,270 | 1.00 |
| BPE | 4,096 | 666,787 | 1.70 |
| BPE | 8,192 | 542,279 | 2.10 |

어휘 2,048 까지는 예산이 글자 조립에 다 쓰여 글자 단위와 같다 — **어휘는 알파벳보다 충분히 커야 병합이 의미를 가진다**.
그 뒤로 어휘를 두 배 늘릴 때마다 시퀀스가 짧아지지만 체감은 줄어든다. 트레이드오프:

| | 어휘 V 큼 | 어휘 V 작음 |
|---|---|---|
| 시퀀스 길이 T | 짧다 → 어텐션(T²) 싸다, 긴 문맥을 본다 | 길다 |
| 토큰 하나의 뜻 | 풍부 (` 생각하였다`) | 빈약 |
| 임베딩 표 V×C (3장) | 크다 | 작다 |
| 드문 토큰 | 학습 기회 적음 | 모두 자주 등장 |

GPT-2 는 50,257, 최근 모델은 10만~25만을 쓴다. 이 프로젝트는 코퍼스가 작아 **8,192** 로 시작하고, 9장에서 어휘 크기별 손실을
비교해 다시 정한다. 결과물은 `data/tokenizers/bpe-8192.json` — 3장부터 이 파일을 읽는다.

주의: 토큰 단위가 달라지면 1장의 loss 는 **토큰당** 값이라 서로 비교할 수 없다. 비교하려면 글자당(또는 바이트당) 으로
환산해야 한다 — 9장에서 다룬다.

## 2.6 실습 — 노트북 02

`notebooks/02-bpe-tokenizer.ipynb` (전체 실행 약 3~4분):

1. 장난감 문자열에서 병합 세 번 따라가기
2. 바이트 BPE 4,096 을 코퍼스에 학습 → 잘린 바이트 토큰 수, 샘플 문장의 토큰
3. 글자 우선 BPE 8,192 학습 → 같은 문장 비교, 어휘 크기별 토큰 수 그래프
4. 처음 보는 글자·이모지 round-trip, `CharTokenizer` 의 `KeyError`
5. `bpe-8192.json` 저장·로드
