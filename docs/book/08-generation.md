# 8장 텍스트 생성: 확률에서 문장을 뽑는 법

모델은 확률을 내놓을 뿐, 문장을 만들지 않는다. 이 장의 질문은 **확률에서 문장을 어떻게 뽑나**다. 1장 바이그램의
`multinomial` 을 그대로 쓰면 되지만, 실제로는 매 스텝 확률 분포를 **조정**한 뒤 뽑는다. 조정 방법 네 가지가 이 장의
내용이고, v1.0 의 성공 기준. "옛날 옛적에" 를 말이 되게 잇기, 를 여기서 확인한다. 노트북
`notebooks/08-generation.ipynb`, 코드 `src/shllm/generate.py`.

## 읽기 전에

- 1장의 `multinomial` (확률대로 하나 뽑기), 6장의 `(B, T, V)` logits, 7장의 `load_checkpoint`.
- softmax 의 성질: 모든 logits 에 같은 수를 더해도 확률은 그대로, 같은 양수로 **나누면** 분포의 뾰족함이 바뀐다. 이것이 temperature 다.

## 핵심 용어

| 용어 | 한 줄 정의 | 비유 |
|---|---|---|
| **디코딩(decoding)** | 확률 분포에서 토큰 열을 만드는 절차 전체 | 악보(확률)에서 연주(문장)로 |
| **greedy** | 매 스텝 최고 확률 토큰 | 항상 1등만 뽑기 |
| **sampling** | 확률대로 무작위로 뽑기 | 가중 추첨 |
| **temperature** | logits ÷ T. T<1 뾰족, T>1 평평 | 조명의 대비 |
| **top-k** | 상위 k 개만 후보로 | 예선 통과자 k 명 |
| **top-p (nucleus)** | 누적 확률 p 까지의 후보만 | "합쳐서 90% 가 될 때까지" |
| **반복 억제** | 이미 나온 토큰의 점수를 깎기 | 같은 카드 다시 뽑기 어렵게 |
| **프롬프트** | 생성을 시작하는 입력 토큰 열 | 문장의 첫 부분 |
| **base 모델** | 이어 쓰기만 배운 모델. 대화·지시는 모른다 | 자동완성 |

## 8.1 생성 루프

```python
for _ in range(max_new_tokens):
    probs = next_token_distribution(model, idx, ...)       # (B, V)  마지막 자리의 조정된 확률
    nxt = torch.multinomial(probs, 1, generator=generator) # (B, 1)
    idx = torch.cat([idx, nxt], dim=1)
```

`next_token_distribution` 은 `idx[:, -block_size:]` 만 넣는다. 문맥이 학습 길이를 넘으면 앞을 잘라 낸다. 그래서 GPT 는
`block_size` 보다 긴 글을 쓸 수는 있지만 그보다 먼 과거는 **잊는다**. 생성 전에 `model.eval()` 로 dropout 을 꺼야 한다.

## 8.2 분포의 모양: 긴 꼬리

노트북 §1: "옛날 옛적에 호랑이가" 다음 토큰 확률은 상위 12개를 합쳐도 15% 남짓, 0.1% 이상인 토큰이 192개다. 소형 모델이
자신 없는 자리에서 보이는 **평평한 분포**다. 문제는 스텝마다 뽑기를 하므로 60 토큰을 쓰는 동안 이 긴 꼬리에서 **한 번이라도**
뽑히면 문장이 산으로 간다는 것이다.
생성 기법은 대부분 이 꼬리를 다루는 방법이다.

## 8.3 조정 네 가지 (`adjust_logits`)

모두 softmax **이전의 logits** 에서 한다. 순서는 반복 억제 → temperature → top-k → top-p.

| 기법 | 코드 | 효과 |
|---|---|---|
| **temperature** T | `logits / T` | T<1: 1등에 몰림(안전·단조). T>1: 평평(다양·산만). T→0: argmax(greedy) |
| **top-k** | k 번째 점수 미만을 −∞ | 꼬리를 통째로 자른다. k 가 고정이라 확실한 상황에서도 k 개가 남는다 |
| **top-p** (nucleus) | 확률순 누적이 p 를 넘는 꼬리를 −∞ | 확실하면 1~2개, 애매하면 수십 개, 상황에 따라 k 가 변한다 |
| **반복 억제** | 이미 나온 토큰의 점수를 나눈다(양수)/곱한다(음수) | 작은 모델의 "…하고 하고 하고" 를 막는다 |

top-p 구현의 요령: 확률순으로 정렬해 누적합을 구하고, **자기 자신을 넣기 전** 누적이 이미 p 를 넘으면 버린다. 이렇게 해야
누적이 p 를 처음 넘기는 토큰까지는 남는다. 정렬한 결과를 `scatter` 로 원래 자리에 되돌린다.

### 단계별 예시: 후보 넷, 조정 셋

어느 자리의 확률이 p = [0.5, 0.3, 0.15, 0.05] (토큰 A, B, C, D) 라고 하자. logits 은 log p = [−0.69, −1.20, −1.90, −3.00].

- **temperature 0.5**: logits ÷ 0.5 = [−1.39, −2.41, −3.79, −5.99] → softmax → **[0.72, 0.26, 0.06, 0.007]**. 1등이 0.5 → 0.72 로 몰렸다.
- **temperature 2.0**: logits ÷ 2 = [−0.35, −0.60, −0.95, −1.50] → **[0.39, 0.30, 0.21, 0.12]**. 평평해졌다. D 가 12% 나 된다.
- **top-k 2**: C, D 를 −∞ → 남은 둘을 다시 정규화 → **[0.625, 0.375, 0, 0]**.
- **top-p 0.7**: 누적 0.5, 0.8, … B 를 넣기 전 누적 0.5 ≤ 0.7 이라 B 까지 남기고 C 부터 자른다 → 역시 [0.625, 0.375, 0, 0]. p 를 0.95 로 올리면 C 까지 남는다.
- **반복 억제 2.0** (A 가 이미 나왔다면): A 의 logit −0.69 는 음수라 ×2 = −1.39 → A 확률 0.5 → 0.33 으로.

`tests/test_generate.py` 가 이 숫자들을 그대로 검사한다.

## 8.4 무엇을 쓸 것인가

노트북 §3 에서 같은 프롬프트·같은 시드로 네 설정을 비교한다.

- **greedy** 는 결정적이지만 같은 구절을 맴돈다. 확률이 가장 높은 길은 대개 "안전한 반복"이다.
- **T=1 그대로** 는 꼬리에서 이상한 토큰이 섞인다.
- **T 0.8 + top-k 50** 이나 **T 0.8 + top-p 0.9 + 반복 억제 1.2** 가 이 크기의 모델에서 가장 읽을 만하다.

소형 모델의 실전값: T 0.7~0.9, top-k 40~50 또는 top-p 0.9, 반복 억제 1.1~1.3. ChatGPT 류의 기본값도 이 근처다.

`small-cpu` best.pt (val 5.485), T 0.8 · top-k 50, 시드 1337:

> 옛날 옛적에 호랑이가 생겨나서, 또 한번 더 짖게 된다. 그러나 나는 또 한번 해뜩으로만 여겨서, 그래서 어떻게 어떻게 하려니 하는 것도 없다.
> 하기야 초봉이를 안 되자한테서 다루 할 것이지만, 가령 제호네 자식한테든지, 그게 바로 그 사람한테나 잘 잘 잘 알고 나서 …

어절·조사·대화 부호("…하고, …라고")는 살아 있고 문장 단위로는 그럴듯하지만, 문단 단위의 뜻은 이어지지 않는다. 49만 토큰으로
학습한 6.8M 모델의 한계이며, v1.0 성공 기준("문법적으로 그럴듯한 문단")의 판정은 사용자 몫이다 (todo P1).

**생성문의 문체.** 결과는 1930년대 소설투(영채·형식·초봉이·"…하였다")다. 모델은 학습 데이터의 분포를 재현할 뿐이라
0장에서 말한 "학습 데이터가 모델을 결정한다"가 여기서 눈으로 확인된다.

### 자바 개발자의 눈으로

| 이 장 | 자바로 치면 |
|---|---|
| `generate` 루프 | `StringBuilder` 에 `next()` 를 붙이는 while. 단 `next()` 가 매번 전체 문맥으로 forward 를 다시 한다 |
| `idx[:, -block_size:]` | `list.subList(max(0, n - T), n)` 슬라이딩 창 |
| `torch.topk(logits, k).values[:, -1]` | 정렬 후 k 번째 값. 그보다 작은 것을 `-inf` 로 |
| `scatter(1, order, sorted_logits)` | 정렬된 배열을 원래 인덱스 위치로 되돌리는 역순열 |
| `torch.Generator().manual_seed(n)` | `new Random(seed)`. 같은 시드 → 같은 문장 |

### 흔한 오해

- **"greedy 가 가장 좋은 문장을 만든다"**, 매 스텝 1등을 고르면 전체적으로는 반복에 빠지기 쉽다(노트북 §3). 확률이 높은 길은 대개 "안전한 반복"이다.
- **"temperature 가 창의성을 만든다"**, 분포를 평평하게 할 뿐이다. 모델이 모르는 것을 알게 하지 않는다. 너무 높이면 꼬리에서 무의미한 토큰이 나온다.
- **"top-k 와 top-p 는 같은 것"**, k 는 고정 개수, p 는 상황에 따라 개수가 변한다. 확실한 자리에서는 p 가 1~2개만 남기고, 애매한 자리에서는 수십 개를 남긴다.
- **"생성이 느린 건 모델이 커서"**, 매 토큰마다 전체 문맥을 다시 계산하기 때문이다. KV 캐시(앞 자리의 K·V 를 저장)를 쓰면 스텝당 계산이 문맥 길이에 비례하지 않게 된다 (todo).

### 데이터가 바뀌면: small-cpu vs mixed-cpu (노트북 §5)

같은 크기, 같은 설정(T 0.8 · top-k 50 · 시드 1337), 다른 데이터.

| 프롬프트 | small-cpu (근대문학) | mixed-cpu (근대문학 + 위키) |
|---|---|---|
| 옛날 옛적에 호랑이가 | …생겨나서, 또 한번 더 짖게 된다. 그러나 나는 또 한번… | …있는 것을, 김씨로 빙숭이를 한다. … 형식은 형벌의 마음에 닿아 있는 방으로… |
| 서울은 대한민국의 수도로, | …것은, 그 중혼원과 라디오가 없는 것이, 그때라, 시언이 없는 계집과… | …대한민국의 국호업생활동으로, 춘추구로동 (1978) 중화인민공화국 (1963년) … 대한민국의 언론인, 연극인, 정치인, 소설가, |
| 그는 아버지의 얼굴을 바라보며 | “왜, 응? 내가 죽였나. 오늘 아침까지 갔나?” | “그렇다” 하고 말을 할 때에는 아무 일로도 알았느냐. 형식의 말에… |

근대문학 프롬프트는 둘 다 소설투를 잇지만, 백과사전식 프롬프트는 mixed 쪽만 그 형식(연도·직업 나열)을 이어 간다.
small-cpu 는 "서울은 대한민국의 수도로" 를 본 적이 없어 소설 어휘로 밀어붙인다. **모델의 세계는 학습 데이터다.** 뜻이 이어지는
문단은 아직 어느 쪽도 못 만든다. 6.8M 파라미터의 한계이며, 다음 단계는 모델을 키우는 것(9장 스케일링)이다.

## 8.5 이 모델과 대화할 수 있나

없다. 이것은 **base 모델**이다. "안녕, 오늘 기분 어때?" 를 넣으면 답하지 않고 그 문장이 소설에 나온 것처럼 **이어 쓴다**.
대화가 되려면 "질문 → 답" 형식의 데이터로 추가 학습(SFT)하고 사람의 선호로 다듬는(RLHF) 과정이 필요하다. 10장이 그 지도이고,
작은 시연을 해 본다.
