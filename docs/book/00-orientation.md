## 핵심 용어 (이 교재 전체에서 쓰는 말)

| 용어 | 한 줄 정의 | 비유 |
|---|---|---|
| **토큰(token)** | 모델이 다루는 최소 단위. 글자 하나일 수도, 단어 조각일 수도 있다 (1~2장) | 자바의 `char` 또는 짧은 `String` 에 붙인 정수 id |
| **어휘(vocabulary), V** | 토큰의 종류 수 | `enum` 의 상수 개수 |
| **문맥(context)** | 지금까지 본 토큰들 | 메서드에 넘어온 입력 리스트 |
| **파라미터(parameter)** | 학습으로 정해지는 숫자들. "가중치(weight)" 와 같은 말 | 설정값이 아니라 데이터로 채워지는 `double[]` |
| **손실(loss)** | 모델이 얼마나 틀렸는지 재는 숫자. 작을수록 좋다 | 테스트 실패 개수 |
| **학습(training)** | 손실이 줄어드는 방향으로 파라미터를 조금씩 고치는 반복 | 실패하는 테스트를 보고 코드를 고치는 루프, 단, 사람이 아니라 미분이 고친다 |
| **생성(generation)** | 학습된 모델로 토큰을 하나씩 뽑아 이어 붙이기 | `while (...) sb.append(next())` |
| **shape** | 텐서의 차원 크기 목록. `(B, T, C)` 처럼 쓴다 | `double[B][T][C]` 의 각 길이 |

## 0.1 LLM 은 결국 무엇을 하는 기계인가

한 문장으로: **"지금까지 나온 글을 보고, 다음에 올 토큰 하나의 확률을 계산하는 함수"** 다.

```
입력: "옛날 옛적에 호랑이가"      →  모델  →  다음 토큰 확률: {" 담배": 0.31, " 살았": 0.22, " 나타": 0.09, ...}
```

**"확률을 계산한다"는 말의 뜻.** 어휘가 V=8,192 개라면 모델의 출력은 길이 8,192 짜리 숫자 배열이고, 각 칸은 "다음 토큰이
이것일 확률", 전부 더하면 1 이다. 위 예에서 " 담배" 칸이 0.31 이라는 것은 "100번 중 31번은 담배가 온다"는 뜻이다.
모델은 정답을 하나로 찍지 않는다. **후보 전부에 점수를 매긴다.** 이 점이 분류기와 다르고, 그래서 같은 프롬프트에서 매번
다른 문장이 나올 수 있다(8장).

이 함수를 한 번 돌려 토큰 하나를 고르고, 그 토큰을 입력 끝에 붙여 다시 돌리는 것을 반복하면 문장이
"생성"된다. ChatGPT 도 이 반복이 전부다. 나머지(대화 형식, 지시 따르기, 안전성)는 이 함수를 **어떤
데이터로 학습시켰는가**의 차이일 뿐이다.

그래서 우리가 만들 것은 정확히 이 함수 하나와, 그것을 데이터로 학습시키는 루프다.

## 0.3 자바 개발자를 위한 Python·PyTorch 최소 지식

Python 은 자바보다 문법이 느슨하지만, 이 프로젝트에서 쓰는 범위는 좁다. 아래만 알면 시작할 수 있다.

| 자바 | Python | 비고 |
|---|---|---|
| `List<Integer> a = new ArrayList<>();` | `a: list[int] = []` | 타입 힌트는 문서일 뿐, 강제하지 않는다 |
| `Map<String,Integer>` | `dict[str, int]` | `{"a": 1}` |
| `for (int i=0; i<n; i++)` | `for i in range(n):` | 블록은 들여쓰기로 |
| `class Foo { Foo(int x) {...} }` | `class Foo:` + `def __init__(self, x):` | `self` 를 명시 |
| `interface` / 추상 클래스 | `torch.nn.Module` 상속 + `forward()` 구현 | 모델은 전부 이 패턴 |
| `import java.util.*` | `import torch` / `from shllm.tokenizer import CharTokenizer` | |
| Maven/Gradle | **uv** (`pyproject.toml` + `uv.lock`) | `uv sync` = 의존성 복원 |
| JUnit | **pytest** (`tests/test_*.py`) | `uv run pytest` |
| `double[][]` | `torch.Tensor` | 차원이 몇 개든 하나의 타입 |

**텐서(Tensor)** 는 "다차원 배열 + 자동미분"이다. `double[][]` 와 다른 점은 셋뿐이다.

1. 연산이 배열 전체에 한 번에 적용된다 (`x * 2`, `x @ w`, 루프를 쓰지 않는다).
2. 모양(`shape`)이 항상 붙어 다닌다. LLM 코드의 버그 대부분은 shape 불일치다. 주석에 shape 를 적는 습관을 들인다.
   예: `x: (B, T, C)` = 배치 B개, 토큰 T개, 채널 C개.
3. `requires_grad=True` 인 텐서는 연산 이력을 기억해 두었다가 `.backward()` 로 미분값을 채운다 (4장).

**PyTorch 모델의 뼈대**는 언제나 이 형태다. 6장까지의 모든 모듈이 이 틀을 따른다.

```python
import torch.nn as nn

class Foo(nn.Module):
    def __init__(self, n_in: int, n_out: int) -> None:
        super().__init__()
        self.linear = nn.Linear(n_in, n_out)   # 학습되는 파라미터를 가진 부품

    def forward(self, x):                      # x: (B, n_in)
        return self.linear(x)                  # → (B, n_out)
```

### 자바 개발자의 눈으로

LLM 은 인터페이스 하나로 요약된다. 이 교재의 모든 모델(1장 확률표부터 6장 GPT 까지)이 이 계약을 지킨다.

```java
interface LanguageModel {
    double[] nextTokenProbs(int[] context);   // 길이 V, 합 1        ← 1장 next_token_probs / 6장 forward
    int[]    generate(int[] start, int n);    // 확률대로 하나씩 뽑기  ← 8장 generate
    double   loss(int[] text);                // 얼마나 틀렸나         ← 1장 loss / 7장 학습이 줄이는 값
}
```

구현이 바뀔 뿐이다: 1장은 `Map<Integer, int[]>` 로 세고, 4장부터는 `double[][]` 행렬 곱과 미분으로 채운다.
"학습"은 이 인터페이스 밖의 일이다. `loss` 가 작아지도록 구현의 숫자를 고치는 별도의 루프(7장)다.

### 흔한 오해

- **"LLM 은 문장을 이해하고 답을 안다"**, 아니다. 다음 토큰 확률을 낼 뿐이다. 이해처럼 보이는 것은 그 확률이 아주 좋아졌을 때의
  결과다(10장). 이 교재의 모델은 작아서 그 착시가 생기지 않는다. 오히려 원리를 보기에 좋다.
- **"GPU 가 없으면 못 한다"**, 크기가 문제일 뿐 원리는 같다. 이 PC 의 CPU 로 7장에서 690만 파라미터 모델을 45분에 학습한다.
  GPT-2 small(1억 2,400만) 과 구조가 같다(6장).
- **"수학을 많이 알아야 한다"**, 행렬 곱 한 가지와 "기울기의 반대 방향으로 조금 움직인다" 한 문장이면 된다. 나머지는 코드다.
