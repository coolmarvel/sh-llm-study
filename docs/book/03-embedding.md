# 3장 — 임베딩: 정수를 벡터로

2장이 끝나면 텍스트는 `[1059, 500, 4149, ...]` 같은 정수 열이다. 이 장의 질문은 **정수 id 를 왜, 어떻게 벡터로 바꾸나**다.
답은 짧다 — `(V, C)` 표에서 행을 꺼낸다. 그런데 그 표의 값에 "뜻"이 담기는 원리, 그리고 순서를 잃지 않기 위한 위치 벡터가
이 장의 내용이다. 노트북 `notebooks/03-embedding.ipynb`, 코드 `src/shllm/embedding.py`.

## 3.1 정수는 숫자가 아니다

토큰 id 1059 와 1060 은 아무 관계가 없다. 정렬 순서일 뿐이라 "1059 가 1060 보다 작다", "1059 + 1 = 1060" 같은 산술은
전부 무의미하다. 그런데 신경망은 곱하고 더하는 기계다. 정수를 그대로 넣으면 모델은 있지도 않은 크기 관계를 배우려 든다.

그래서 각 토큰을 **서로 독립인 방향**으로 놓는다. 가장 단순한 방법이 **원-핫(one-hot)**: 길이 V 의 벡터에서 자기 자리만 1.

```
id 3 (V=6)  →  [0, 0, 0, 1, 0, 0]
```

원-핫끼리는 모두 직교하고 거리가 같다 — 관계가 없다는 사실을 정직하게 표현한다. 문제는 V=8,192 차원이 너무 크고
희소하다는 것, 그리고 여전히 "비슷한 토큰"이라는 정보가 없다는 것이다.

## 3.2 룩업 테이블 = 원-핫 × 행렬

원-핫 벡터 `(V,)` 에 행렬 `W (V, C)` 를 곱하면 결과는 W 의 **한 행**이다 (1 인 자리의 행만 살아남는다). 그러니 곱셈을 하지 않고
행을 꺼내면 된다. 이것이 `nn.Embedding` 의 전부이며, `TokenEmbedding` 은 그것을 두 줄로 쓴 것이다:

```python
class TokenEmbedding(nn.Module):
    def __init__(self, vocab_size, n_embd):
        super().__init__()
        self.weight = nn.Parameter(torch.randn(vocab_size, n_embd) * 0.02)   # (V, C)

    def forward(self, idx):          # idx: (B, T) 정수
        return self.weight[idx]      # → (B, T, C)
```

두 가지가 중요하다.

- **`weight[idx]`** — 정수 텐서로 인덱싱하면 각 id 의 행이 그 자리에 꽂힌다. `(B, T)` 를 넣으면 `(B, T, C)` 가 나온다.
  자바로 치면 `double[V][C]` 에서 `idx` 마다 행을 복사해 `double[B][T][C]` 를 만드는 것.
- **`nn.Parameter`** — "이 텐서는 학습 대상"이라는 표시. 4장의 optimizer 는 모델 안의 Parameter 를 전부 찾아 갱신한다.
  즉 임베딩 표의 값은 처음엔 랜덤이고, 학습이 그 값을 정한다.

노트북 §1 에서 `one_hot_lookup` 과 결과가 같음을 확인한다. 0.02 를 곱하는 초기화는 GPT-2 의 값으로, 처음 벡터를 작게 두어
학습 초기에 신호가 폭주하지 않게 한다.

## 3.3 벡터에 뜻이 생기는 원리 — 분포 가설

C 차원 벡터는 원-핫과 달리 **서로 가까울 수 있다**. ` 아버지` 와 ` 어머니` 의 벡터가 비슷하면, 한쪽에서 배운 것이 다른 쪽에
자동으로 옮겨진다 — 1장 끝에서 n-gram 표가 못 하던 바로 그 일반화다. 그런데 무엇이 두 벡터를 가깝게 만드나?

**"비슷한 문맥에 나오는 토큰은 비슷한 뜻이다"** (분포 가설, Harris 1954). 벡터를 만드는 방법은 이 가설을 구현하는 두 갈래다.

| 방법 | 원리 | 어디서 |
|---|---|---|
| **세기** | 앞뒤에 같이 나온 횟수 표 `(V, V)` 를 만들고 저차원으로 압축 | 이 장 노트북 §2 (PPMI + SVD) |
| **학습** | 다음 토큰 예측 손실이 줄어드는 방향으로 표를 조금씩 고침 | 4장부터, 실제 GPT |

세는 방법은 학습이 필요 없어 지금 바로 해 볼 수 있다. 절차:

1. `cooccurrence_matrix` — 각 토큰의 앞뒤 2칸 안에 어떤 토큰이 몇 번 왔는지 `(V, V)` 로 센다. 1장 바이그램의 "어긋나게
   겹치기"를 거리 1, 2 에 대해 양방향으로 한 것이다.
2. `ppmi` — 횟수를 그대로 쓰면 `는`·`,` 같은 흔한 토큰이 모든 행을 지배한다. PMI = log P(a,b) / (P(a)P(b)) 는 "우연보다
   얼마나 더 자주 같이 나오나"라 빈도 효과가 빠진다. 음수는 불안정해 0 으로 자른다.
3. `svd_embeddings` — `(V, V)` 행렬을 SVD 로 `(V, C)` 로 압축. 행렬 ≈ E Eᵀ 가 되게 하는 E 의 상위 C 개 방향만 남긴다.
   1장의 확률표를 C 차원으로 "요약"한 것이 임베딩이라는 감각이 여기서 온다.

결과 (노트북 §2, 상위 4,000 토큰, C=64):

| 토큰 | 코사인 유사도 상위 이웃 |
|---|---|
| ` 아버지` | ` 어머니` · ` 언니` |
| ` 돈` | ` 원` · ` 이백` · ` 이천` · ` 오백` |
| ` 없다` | ` 없었다` · ` 없습니다` · ` 없고` · ` 있다` |
| `는` | `가` · `를` · `고` · `와` |
| `,` | `……` · ` 또` · ` 그런데` |

**아무도 뜻을 가르치지 않았다.** 같은 자리에 나오는 토큰이 같은 방향의 벡터가 됐을 뿐이다. 조사끼리, 금액끼리, 가족끼리
모이는 것은 코퍼스가 그렇게 쓰였기 때문이다. word2vec 같은 학습형 방법이 사실상 이 행렬을 분해하는 것과 같다는 것이
알려져 있다(Levy & Goldberg 2014). 학습형은 다음 토큰 예측이라는 목적에 맞춰 더 정교해질 뿐, 원리는 같다.

**코사인 유사도** — 두 벡터의 방향이 얼마나 같은가: `a·b / (|a||b|)`. 1 이면 같은 방향, 0 이면 직교. 벡터의 길이(빈도의
영향을 많이 받는다)를 무시하고 방향만 비교하려고 쓴다 (`nearest`).

## 3.4 위치 임베딩 — 순서를 잃지 않기

토큰 임베딩만 있으면 `[개, 가, 사람, 을, 물었다]` 와 `[사람, 이, 개, 를, 물었다]` 는 벡터의 **집합**으로는 거의 같다.
5장 어텐션은 벡터들의 가중 합이라 태생적으로 순서를 모른다. 그래서 "몇 번째 자리인가"도 벡터로 만들어 토큰 벡터에
**더한다**.

두 방식이 있다.

| | sin/cos (`sinusoidal_positions`) | 학습 (`LearnedPositionalEmbedding`) |
|---|---|---|
| 값 | 열마다 주기가 다른 sin·cos 함수. 고정 | `(T_max, C)` 표. 학습됨 |
| 길이 제한 | 없음 (공식이라 아무 위치나 계산) | `block_size` 를 넘으면 처리 불가 |
| 쓰는 곳 | 원조 Transformer (2017) | GPT-2, 이 프로젝트 |

sin/cos 는 앞쪽 열이 빠르게 진동해 이웃 위치를, 뒤쪽 열이 느리게 변해 먼 위치를 구분한다. 노트북 §3 의 유사도 그림에서
가까운 위치일수록 벡터가 비슷하다 — "거리"가 벡터 안에 들어 있다. 학습형은 더 단순하고 GPT-2 규모에서는 성능 차이가
없어 우리도 학습형을 쓴다. 대신 학습한 길이(`block_size`)가 곧 모델이 볼 수 있는 최대 문맥이 된다.

**왜 연결(concat)이 아니라 덧셈인가.** C 차원이 충분히 크면 토큰 정보와 위치 정보가 서로 다른 방향을 차지해 섞이지 않고
공존한다. 덧셈은 차원을 늘리지 않아 이후 모든 층이 `(B, T, C)` 하나만 다루면 된다.

## 3.5 GPTEmbedding — 모델의 입구

```python
class GPTEmbedding(nn.Module):
    def forward(self, idx):            # (B, T)
        tok = self.tok(idx)            # (B, T, C)
        pos = self.pos(T)              # (T, C)  ← 배치 축 없이, 브로드캐스팅으로 더한다
        return tok + pos               # (B, T, C)
```

파라미터 수 (V=8,192, T_max=256, C=256):

| 표 | 크기 | 파라미터 |
|---|---|---|
| 토큰 | 8,192 × 256 | 2,097,152 |
| 위치 | 256 × 256 | 65,536 |

임베딩 비용은 거의 전부 어휘 크기 V 다 — 2장의 트레이드오프가 숫자로 보인다. 6장의 GPT 는 이 `(B, T, C)` 를 받아 같은
모양을 유지하며 값만 바꿔 나간다.
