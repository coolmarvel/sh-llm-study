# 10장 여기서 ChatGPT 까지

9장까지로 "지금까지의 글을 보고 다음 토큰의 확률을 계산하는 함수"(0장)를 밑바닥부터 만들고, 학습하고, 생성하고, 평가했다.
이 장의 질문은 **여기서 ChatGPT 까지는 무엇이 더 필요한가**다. 답은 네 가지, 규모, 지시 파인튜닝, 선호 학습, 그리고
모델 밖의 도구. 개념 지도가 중심이고, 노트북 `notebooks/10-beyond.ipynb` 에서 그중 하나(SFT)를 작게 시연한다
(`src/shllm/sft.py`).

## 읽기 전에

- 8장의 base 모델과 생성, 7장의 학습 루프. 이 장은 새 코드보다 **개념 지도**가 목적이다.
- 이 장의 시연 코드는 `finetune` (7장 루프의 축소판) 과 `answer` (8장 greedy 생성) 둘뿐이다.

## 핵심 용어

| 용어 | 한 줄 정의 | 비유 |
|---|---|---|
| **사전학습(pretraining)** | 대량 텍스트로 다음 토큰 예측을 배우는 것. 1~9장 전부 | 기초 교육 |
| **SFT (지시 파인튜닝)** | "지시 → 답" 예제로 형식과 태도를 추가 학습 | 직무 교육 |
| **RLHF / DPO** | 사람이 고른 선호 쌍으로 답의 질을 다듬기 | 코드 리뷰로 스타일 교정 |
| **보상 모델** | "이 답이 얼마나 좋은가"를 점수로 내는 별도 모델 | 심사위원 |
| **환각(hallucination)** | 모르는 것을 그럴듯하게 지어내는 현상 | 자신 있게 틀린 답 |
| **RAG** | 답하기 전에 관련 문서를 검색해 문맥에 넣기 | 오픈북 시험 |
| **function calling** | 모델이 도구(계산기·API)를 호출하도록 출력 형식을 정하기 | 외부 서비스 호출 |
| **정렬(alignment)** | 모델의 행동을 사람의 의도·안전 기준에 맞추는 일 전반 | 사규 준수 |

## 10.1 규모: 같은 구조, 다른 숫자

| | 이 프로젝트 | GPT-2 (2019) | 최근 공개 모델 |
|---|---|---|---|
| 파라미터 | 6.8M | 124M ~ 1.5B | 7B ~ 수백 B |
| 학습 토큰 | 49만 | 수십억 | 수조 |
| 문맥 길이 | 128 | 1,024 | 수만~수십만 |
| 구조 | 6장 GPT 와 같음 | 같음 | 거의 같음 (RoPE·GQA·SwiGLU 등 부품 교체) |

구조는 6장에서 만든 것과 같다. 차이는 숫자와, 그 숫자를 감당하는 공학(GPU 수천 대의 병렬화, 데이터 정제)이다.
9장의 스케일링에서 본 대로 모델·데이터·계산을 함께 키우면 loss 가 예측 가능하게 내려가고, 어느 지점부터 "지식"과
"추론"처럼 보이는 능력이 나타난다.

## 10.2 지시 파인튜닝 (SFT): 형식을 가르친다

8장의 base 모델은 질문에 답하지 않고 이어 쓴다. "질문: … 답: …" 형식의 데이터로 **같은 모델을 조금 더 학습**시키면
그 형식을 따르기 시작한다. 이것이 supervised fine-tuning 이고, 7장 학습 루프와 다른 점은 데이터의 모양뿐이다.

노트북 §2~3: 코퍼스의 작품 목록(작가·제목)으로 질문-답 80개를 만들어 200 스텝 학습한다 (`build_examples`, `finetune`).
질문 부분에는 loss 를 주지 않는다(`ignore_index=-100`), 질문을 외우는 것이 목적이 아니다. 결과:

- "봄봄의 작가는 누구인가?" → "김유정" (학습에 있던 질문)
- "동백꽃을 쓴 사람은?" → 맞힌다 (다른 템플릿)
- "홍길동전의 작가는 누구인가?" → **그럴듯한 작가 이름을 댄다** (코퍼스에 없는 작품)

마지막이 **환각(hallucination)** 의 원리다. 모델은 "답: " 다음에 올 확률이 높은 토큰을 낼 뿐, 아는지 모르는지를 구분하는
장치가 없다. 실제 SFT 는 수만~수백만 개의 다양한 대화·작업 예제를 쓰고, "모르겠습니다"라고 답하는 예제도 들어 있다.

## 10.3 선호 학습 (RLHF · DPO): 어느 답이 더 좋은가

SFT 만으로는 "형식은 맞지만 틀리거나 무례한" 답을 거르지 못한다. 같은 질문에 대한 답 두 개를 사람이 비교해 고른 데이터로,
**더 선호되는 답의 확률을 올리고 덜 선호되는 답의 확률을 내리는** 학습을 한다.

- **RLHF**: 선호 데이터로 "보상 모델"을 먼저 학습하고, 그 보상을 최대화하도록 강화학습(PPO). ChatGPT 의 원래 방식.
- **DPO**: 보상 모델 없이 선호 쌍에서 직접 손실을 정의. 더 단순해 최근 공개 모델이 많이 쓴다.

안전성(거절), 말투, "모르면 모른다고 하기"가 대부분 이 단계에서 결정된다. 0장에서 말한 "나머지는 어떤 데이터로 학습시켰는가의
차이"가 바로 이것이다.

## 10.4 모델 밖: 검색(RAG) 과 도구

모델의 지식은 학습 시점에 고정되고 환각을 피할 수 없다. 그래서 답하기 전에 **관련 문서를 검색해 문맥에 넣어 주는** 방식(RAG,
retrieval-augmented generation)이 쓰인다. 3장의 임베딩이 여기서 다시 등장한다. 질문과 문서를 벡터로 바꿔 가까운 것을 찾는다.
계산기·코드 실행·API 호출 같은 **도구**를 모델이 부르게 하는 것(function calling)도 같은 발상이다: 모델이 못 하는 일은 모델 밖에서.

### 자바 개발자의 눈으로

| 개념 | 자바 세계의 대응 |
|---|---|
| 사전학습 → SFT → RLHF | 라이브러리 → 애플리케이션 → 운영 피드백 반영. 같은 바이너리에 계층이 쌓인다 |
| 프롬프트 형식 (`질문: … 답: `) | 프로토콜. 양쪽이 같은 형식을 써야 통한다 |
| `ignore_index=-100` | 손실 계산에서 제외할 자리를 표시하는 sentinel |
| RAG | 캐시 미스 때 DB 조회 후 응답에 포함 |
| function calling | JSON 으로 메서드 이름·인자를 내고 런타임이 실행 |

### 흔한 오해

- **"SFT 를 하면 모델이 새 지식을 배운다"**, 80개 예제로 형식은 배웠지만 "홍길동전"은 모른다. SFT 는 주로 **형식과 태도**를, 지식은 사전학습 데이터에서 온다.
- **"환각은 버그라서 고칠 수 있다"**, 다음 토큰 확률을 내는 구조에서 "모른다"는 상태가 따로 없다. 완화(RAG, 거절 예제, 선호 학습)는 가능하지만 제거는 안 된다.
- **"우리 모델은 작아서 대화가 불가능하다"**, 형식은 배운다(노트북 §3). 내용이 빈약한 것은 지식(데이터) 문제이지 구조 문제가 아니다.
- **"ChatGPT 는 우리 GPT 와 다른 기술"**, 같은 구조(6장)에 규모·데이터·SFT·선호 학습이 더해진 것이다. 0장의 정의는 그대로다.

## 10.5 이 프로젝트의 다음

- **데이터**: 코퍼스 2차 확장(한국어 위키 일부). 7장의 과적합이 가장 먼저 풀린다.
- **문맥·구조**: block_size 512, RoPE 위치 부호화, KV 캐시로 생성 속도.
- **대화**: 진짜 한국어 대화 데이터로 SFT. CPU 소형 모델에서도 "형식"은 배울 수 있음을 이 장에서 봤다.

## 스스로 점검

1. base 모델에 질문을 넣으면 왜 소설을 이어 쓰는가? SFT 200 스텝 후에는 왜 답을 하는가?
2. 질문 부분에 loss 를 주지 않는 이유는?
3. "현진건의 작품 중 하나는?" 에 "김유정" 이라고 답한 현상의 이름과 원인은?
4. RLHF 와 DPO 의 공통 목표와 차이는?
5. RAG 가 환각을 줄이는 원리를 3장 임베딩과 연결해 설명하라.
6. 이 프로젝트에서 "대화가 되는 모델"까지 남은 것을 데이터·학습·평가 세 축으로 말하라.
